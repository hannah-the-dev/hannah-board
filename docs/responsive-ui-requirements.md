# Hannah Board 반응형 UI 요구사항

## 1. 문서 목적

현재의 컨트롤러·DTO·서비스 구조를 유지하면서, 모바일과 데스크톱에서 모두 사용하기 쉬운 심플한 화면을 구성한다. 화면은 Thymeleaf 템플릿 기반으로 구현하며, 공통 헤더와 좌측 햄버거 메뉴를 사용한다.

## 2. 현재 구조 반영

| 기능 | 현재 진입점 | 현재 모델/서비스 | 요구사항 반영 |
| --- | --- | --- | --- |
| 회원가입 | `GET/POST /signup` | `UserRequest`, `UserResponse`, `UserService.signUp()` | 가입 성공 후 자동 로그인 및 `myinfo` 이동 |
| 회원 정보 | `GET /user/{id}` | `UserResponse`, `UserService.getUser()` | 로그인 사용자 정보 표시 |
| 게시판 목록 | `GET /board/list` | `Page<PostResponse>`, `PostService.getList()` | 반응형 목록 및 글쓰기 진입 |
| 글쓰기 | `GET /post/write` | `Post`, `write.html` | 입력 폼 제공 |
| 글 저장 | `POST /post/save` | `PostService.write()` | 저장 후 조회 화면에서 저장 결과 표시 |
| 글 조회 | `GET /post/{id}` | `PostResponse`, `PostService.getPost()` | 기존 조회 서비스는 조회수 증가 목적이므로 저장 직후 표시에는 사용하지 않음 |

현재 `UserService.login()`은 존재하지만 로그인 컨트롤러와 로그인 템플릿이 없으므로 로그인 기능을 추가 구현 대상으로 정의한다. 또한 현재 보안 설정은 모든 요청을 허용하므로, 로그인 상태 표현은 우선 세션 기반으로 구성하고 이후 Spring Security 인증 객체로 확장할 수 있도록 한다.

## 3. 화면 및 사용자 흐름

### 3.1 인덱스 화면 `/`

- 서비스명과 간단한 안내 문구를 표시한다.
- 다음 바로가기를 제공한다.
  - 회원가입: `/signup`
  - 로그인: `/login`
  - 게시판: `/board/list`
- 화면 폭에 따라 바로가기 카드는 1열 또는 3열로 배치한다.
- 공통 햄버거 메뉴를 사용할 수 있다.

### 3.2 로그인 화면 `/login`

- 아이디와 비밀번호를 입력받는다.
- 로그인 성공 시 해당 사용자의 `myinfo` 화면(`/user/{id}`)으로 이동한다.
- 로그인 실패 시 다음 정책에 따라 입력 화면에 오류 메시지를 표시한다.
  - 아이디가 존재하지 않음: `ID가 올바르지 않습니다`
  - 비밀번호 불일치: `비밀번호가 올바르지 않습니다`
  - 그 외 로그인 처리 실패: `로그인에 실패했습니다`
- 로그인 상태에서는 메뉴에 `내 정보`를 표시한다.

### 3.3 회원가입 화면 `/signup`

- 아이디 중복 확인, 비밀번호 입력, 가입 버튼을 제공한다.
- 아이디 변경 시 중복 확인 상태를 초기화한다.
- 가입 성공 시 별도의 로그인 화면을 거치지 않고 자동 로그인 처리 후 `/user/{id}`로 이동한다.
- 중복 아이디와 유효하지 않은 입력은 화면에 오류를 표시한다.

### 3.4 내 정보 화면 `/user/{id}` (`myinfo`)

- 로그인한 사용자의 아이디, 역할, 상태, 가입일을 표시한다.
- 비밀번호는 표시하지 않는다.
- 비로그인 사용자가 접근할 경우 로그인 화면으로 유도한다.
- 현재 `UserResponse` 필드(`id`, `username`, `role`, `status`, `createdAt`)를 기준으로 구성한다.

### 3.5 게시판 목록 `/board/list` (`board`)

- 게시글의 제목, 작성일, 조회수를 표시한다.
- 각 게시글을 선택하면 `/post/{id}`로 이동한다.
- `글쓰기` 버튼을 제공하고 `/post/write`로 이동시킨다.
- `글쓰기` 버튼은 로그인한 회원에게만 노출한다.
- 기존 페이지네이션을 유지하되 모바일에서는 가로 스크롤 없이 축약된 형태로 표시한다.
- 게시글이 없을 때 빈 상태 안내를 표시한다.

### 3.6 글쓰기 `/post/write` (`write`)

- 제목과 내용을 입력받는다.
- 조회수 입력 필드는 노출하지 않고 서버가 관리한다.
- 저장 버튼 클릭 시 `POST /post/save`를 호출한다.
- 저장 성공 후 저장된 게시글의 식별자를 이용해 조회 화면으로 이동한다.

### 3.7 저장 직후 조회 화면 `/post/{id}` (`post`)

- 저장한 제목과 내용을 화면에 표시한다.
- 저장 직후 결과 표시를 위해 조회수를 증가시키는 `PostService.getPost()`를 호출하지 않는다.
- 별도의 조회 전용 서비스를 구현하지 않는다.
- 저장 처리에서 생성한 저장용 DTO 객체를 리다이렉트 과정에서 `/post/{id}`로 전달하고, `post` 화면은 전달받은 DTO를 사용해 표시한다.
- 저장용 DTO가 전달되지 않은 일반적인 `/post/{id}` 접근은 기존 게시글 조회 흐름으로 처리한다.
- 기존 사용자가 게시판에서 게시글을 열어보는 일반 조회 흐름은 현재 조회 정책을 유지한다.
- 사용자 본인이 작성한 글 인 경우, `게시글 수정` 버튼을 제공하고 `/post/edit`로 이동시킨다.

## 4. 공통 햄버거 메뉴

- 모든 주요 화면의 좌측에 햄버거 버튼을 배치한다.
- 버튼을 누르면 좌측 사이드 메뉴가 열리고 다시 누르거나 바깥 영역을 누르면 닫힌다.
- 메뉴 항목은 다음과 같다.
  - 홈: `/`
  - 내 정보: 로그인한 경우에만 노출하며 `/user/{id}`로 이동
  - 게시판: `/board/list`
  - 로그인 또는 회원가입: 비로그인 상태에서 노출
- 키보드 포커스와 `Esc` 키 닫기를 지원한다.
- 메뉴가 열릴 때 본문과 시각적으로 구분되는 오버레이를 표시한다.

## 5. 반응형 UI 기준

- 모바일 우선으로 작성한다.
- 기준 구간은 다음과 같이 적용한다.
  - 모바일: `0~767px`, 단일 열, 좌우 여백 16px
  - 태블릿: `768~1023px`, 콘텐츠 최대 폭 720px
  - 데스크톱: `1024px 이상`, 콘텐츠 최대 폭 960px
- 버튼과 입력 요소의 최소 터치 영역은 44px 이상으로 한다.
- 고정 폭 `500px` 레이아웃을 제거하고 `width: 100%`, `max-width` 중심으로 구성한다.
- 색상, 간격, 버튼, 카드, 폼 스타일은 공통 CSS로 관리한다.
- 테이블은 모바일에서 카드 목록 또는 필요한 열만 노출하는 방식으로 변환한다.
- 한글 텍스트가 깨지지 않도록 모든 HTML의 문자 인코딩을 UTF-8로 통일한다.

## 6. 컨트롤러·서비스 변경 요구사항

1. 루트 경로 `/`를 반환하는 인덱스 컨트롤러를 추가한다.
2. 로그인 화면과 로그인 처리 엔드포인트를 추가한다.
3. 회원가입 성공 시 로그인 세션을 생성하고 사용자 정보 화면으로 이동한다.
4. 로그인 사용자 식별 정보를 공통 레이아웃에서 사용할 수 있도록 모델 또는 세션 처리 방식을 통일한다.
5. `POST /post/save`는 저장된 `Post`의 id를 기준으로 결과 화면으로 이동한다.
6. 저장 처리에서 저장용 DTO를 생성하고, `RedirectAttributes`의 flash attribute 또는 이에 준하는 일회성 전달 방식으로 `/post/{id}`에 전달한다.
7. `/post/{id}`는 전달받은 저장용 DTO가 있으면 해당 DTO를 우선 사용하고, 없을 때만 기존 게시글 조회 흐름을 사용한다.
8. `PostResponse` 또는 별도 저장용 DTO를 사용해 화면에 표시하며 비밀번호 등 민감정보는 모델에 포함하지 않는다.

## 7. 완료 기준

- `/`에서 회원가입, 로그인, 게시판으로 이동할 수 있다.
- 정상 로그인 후 `myinfo`에서 로그인한 사용자 정보가 보인다.
- 회원가입 직후 자동 로그인되어 `myinfo`로 이동한다.
- 게시판에서 글쓰기 → 저장 → 저장한 글 화면 표시가 연속으로 동작한다.
- 저장 직후 표시 과정에서 조회수가 증가하지 않는다.
- 햄버거 메뉴가 모바일·데스크톱에서 정상적으로 열리고 닫힌다.
- 모바일 폭에서 가로 스크롤 없이 모든 주요 화면을 사용할 수 있다.
- 기존 게시판 페이지네이션과 게시글 일반 조회가 동작한다.

## 8. 확정 정책

- 로그인 실패 메시지
  - ID가 존재하지 않으면 `ID가 올바르지 않습니다`
  - 비밀번호가 일치하지 않으면 `비밀번호가 올바르지 않습니다`
  - 그 외 오류는 `로그인에 실패했습니다`
- 비밀번호 정책은 초기 버전에서 별도로 적용하지 않는다.
- 로그아웃 메뉴는 초기 버전 범위에서 제외한다.
- 저장 직후 화면의 URL은 `/post/{id}`를 사용한다.
- 저장 직후에는 별도의 조회 서비스를 구현하거나 호출하지 않는다.
- 저장용 DTO 객체를 `/post/{id}`에 전달해 저장된 제목·내용 등을 표시한다.

위 정책에 따라 현재 엔드포인트를 최대한 유지하며, 일반 게시글 조회에서만 기존 조회수 증가 흐름을 사용한다.
